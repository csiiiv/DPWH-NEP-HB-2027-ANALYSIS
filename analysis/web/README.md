# FY2027 React workbenches

`Workbench.jsx` selects DPWH, DA farm-to-market roads, DOH health facilities, NIA irrigation, or
Geolocation from the hash route. The shared header uses `routes.js` to render each workspace's
navigation. Annex apps and browser datasets load when their workspace opens.
The FMR workflow is described below; see the
[NIA workbench guide](../../analysis-nia/NIA_WORKBENCH.md) for irrigation views.
NIA Compare follows DPWH's compact table workspace and inline PDF layout.
NIA Analysis retains Overview, Insertions, Deletions, Adjustments, Statistics,
Candidates and Agency controls, with an additional AI monitoring tab. Additional tables show allocation shares in
Overview, funding reconciliation and pairing coverage in Candidates, and
source-specific top-ten concentration with evidence drilldowns in Statistics.
AI monitoring uses the same source selector, filters, tables and exports to
show whole project allocations whose titles mention AI monitoring, including
separately labeled NEP OCR variants checked against the PDF. The tab also shows
House-only AI monitoring insertion-candidate counts and allocations, with
filter-aware shares and supporting-record CSV/PDF evidence.

## Main Overview

The shared **Overview** tab precedes DPWH and opens by default at an empty hash
or `#overview`. Explicit DPWH `#home` and annex/source routes keep their previous
destinations. Geolocation remains registered alongside the four funding apps.

`MainOverview.jsx` loads only `analysis/main_overview_2027.json`, generated by
`buildMainOverview.mjs` after the workspace builders. Its adapters reuse the
Analysis model populations, validate source records and financial bridges, and
record input hashes. Main cards show insertion/deletion candidates and separate
gross increase, gross reduction and net adjustment movement. DPWH grouped
members count as allocation records; HFEP counts printed funding-column records.
HFEP's local NEP-minus-House convention is reversed explicitly on the landing
page, and the documented ₱140,000 control residual stays separate.

`#overview?exact=1` restores exact-PHP display. Table sorting and table links
also persist in the URL. Summary CSV/JSON exports preserve exact amounts,
counting units, comparison bases and supporting routes.

Validate after packaging with `python scripts/check_overview_pages.py`.
See [main Overview plan](../docs/main_overview_page_plan.md).

The unlisted Experiments workspace includes **Budget flow** at
`#experiments?tab=budget`: a five-stage NEP total → category groups → per-group revision cells →
category groups → HGAB total view with side-specific bands, selection, supporting Compare
records and SVG/PNG downloads. It reuses `dpwh_flow_2027.json`; no additional
project payload is loaded. Insertions/deletions remain explicitly labeled
candidates. Run `python scripts/check_budget_flow_pages.py` after packaging.
See [category implementation notes](../../experiments/docs/Budget%20Flow%20Categories%20-%20Implementation%20Notes.md).

**NEP → Category → PAP** at `#experiments?tab=nep` shows a three-column,
amount-weighted DPWH NEP Sankey. It reuses the `nep_hierarchy` rollup in
`dpwh_flow_2027.json`, retains every positive PAP allocation within its parent
category, separates FAPs, and supports category focus and exact-peso labels.
The NEP total reflects the retained comparison ledger's coverage.

**HGAB3 → Category → PAP** at `#experiments?tab=hgab3` provides the matching
House 3rd-reading hierarchy, using `hgab3_hierarchy` from the same payload.
It uses third-reading pesos and grouping labels, includes House-only allocations,
and shares the NEP chart's category filter and exact-peso display.

Both hierarchies extend to **Category → PAP → Region → DEO / implementing office**.
Use **Display through** to choose the final column (PAP by default), then narrow
the category, PAP and region. Depth and filters survive reloads and sharing via
`through=region|deo`, `category`, `pap` and `region` hash parameters. Region and
office nodes retain their full parent paths. Office assignments come from the
selected ledger, including Central Office, regional offices and explicit missing
labels; grouped source records split by their own allocations without double counting.
Validate all depths and filter restoration with `python scripts/check_hierarchy_pages.py`.

**Download section PNG** and **Download SVG** export the complete allocation
hierarchy at the selected depth and scope, including off-screen branches,
column headings, exact total and source notes. PNG fits browser image limits;
SVG preserves full detail for large regional and office views. Exporting leaves
the live filters and scroll position unchanged.

## Development and packaging

From the repository root, using Node 22 and Python 3:

```sh
npm ci --prefix analysis/web
npm run dev --prefix analysis/web
```

`predev` and `prebuild` rebuild the comparison payloads and run
`other-analysis/build_fmr_workbench.py`, `other-analysis/build_hfep_workbench.py`,
`analysis-nia/build_nia_workbench.py`, and `gps-analysis/build_gps_workbench.py`. Vite's retained
file middleware serves JSON, source PDFs with byte ranges, review images, and
source documentation from the checkout.

```sh
npm run build --prefix analysis/web
python scripts/build_pages.py --with-react
python scripts/serve_pages.py --port 8000
```

Open `http://127.0.0.1:8000/`. Use this complete package for previews with source
evidence. Relative URLs also work under a GitHub Pages project prefix.

## Main tabs

FMR routes below. NIA and HFEP reuse the same tab keys under `#nia/` and
`#hfep/`; NIA Analysis views and params are listed in
[NIA_WORKBENCH.md](../../analysis-nia/NIA_WORKBENCH.md).

| Route | Content |
|---|---|
| `#home` | Source totals, budget difference, and workspace links |
| `#highlights` | Coverage/change tables and findings with evidence dialogs |
| `#compare` | Regional controls and project candidate comparisons |
| `#analysis` | Overview, candidate rankings, adjustments, coordinates, allocation statistics |
| `#house` | Supplied House GAB source tree, projects, coordinate review |
| `#nep` | DBM NEP source tree, projects, coordinate review |

Source pages accept `view=tree|projects|review`, `node`, `q`, `region`, `status`,
and `category`. The tree sits above selected arithmetic/evidence; the selected
PDF renders in a sticky desktop column and stacks below the workspace on mobile.
Mobile has explicit results/evidence controls. Review categories overlap;
previous/next navigation respects the region, category and search scope.

Compare accepts `view=regions|projects`, `region`, `q`, `status`, `direction`,
`method`, `coordinate`, `pair`, `sort`, `dir`, and `page`. Sorting covers the
whole filtered ledger before 50-row pagination. Copying a link or reloading
preserves the page and sorting. Filters reset pagination. CSV and JSON exports
include every filtered row and retain source-local IDs, titles, exact amounts,
and PDF provenance. Mobile uses labeled cards with its own sort control.

Analysis accepts `stage=nep|house` and
`view=overview|insertions|deletions|adjustments|coordinates|stats`.
`records=region:<key>|band:<index>|amount:<pesos>|all` opens a supporting source
record dialog. Earlier `house_candidates`, `nep_candidates`, `chainage`, and
`statistics` view links resolve to their canonical views. Candidate populations stay
provisional. Coordinates show endpoint-distance diagnostics, not construction
cost/km: the source supplies no road chainage or constructed road length.

Highlights accepts `story=<finding-id>` and story filters. Coverage and candidate
funding-change tables appear first. Each of the eight findings opens its own
fact panel, supporting records/controls, exports, PDF evidence and onward link.

HFEP and FMR highlight actions are contextual buttons with three source-derived
key figures, an investigation question and evidence limits. Counts follow the
available findings. Existing `story` IDs remain shareable.
HFEP's funding story reconciles printed columns and category controls, while
House balance exposes every internal control. `evidenceNode` selects a House
control or a reviewed NEP facility within its highlight dialog. The extraction
population includes both flagged and interpreted facilities, counted once.
The `hospital-priorities` story asks why DOH hospital allocations fall while
LGU hospital allocations rise, with the two printed category controls and both
hospital source populations. `evidenceStage=nep|house` selects a source and
`evidenceNode` restores the selected hospital record. The former `agency-check`
story link remains an alias. Annex/MOOE reconciliation is now a collapsed scope
note within the capital-outlay reduction story (`lgu-split`).
FMR funding stories include regional bridges and supporting candidate records;
`evidenceProject` selects coordinate/segment evidence within a source story.
`evidencePopulation=open|history` separates remaining coordinate findings from
original extraction flags, including NEP's empty open population.
Run `python scripts/check_annex_highlights.py` after packaging to validate these
actions on desktop and mobile. See [highlight evidence review](../docs/highlights_evidence_review.md)
for the findings and editorial review notes.

`readingNote` links the bounded House comparison: extracted text is identical on
all 60 FMR annex pages (PDF 667–726) in the retained 2nd/3rd-reading copies. The
app still uses the normalized working-copy ledger; it does not fabricate a
separately extracted third-reading stage.

Unknown routes and invalid evidence selections show recovery actions. PDF
references use explicit FMR document metadata rather than the DPWH registry.

## Reusable revision flows

The Budget flow experiment uses a general five-stage builder:
`Total A → Intermediary A → Revision Matrix → Intermediary B → Total B`.
`src/revisionFlow.js` builds the validated graph, `src/revisionFlowLayout.js`
positions it, and `src/RevisionFlowDiagram.jsx` renders it. Grouping, stage
labels, value formatting and selection callbacks are supplied by callers.
The Budget flow tab also offers four datasets (DPWH, FMR, HFEP, NIA) and their
recorded intermediary fields. `buildBudgetFlowSources.mjs` builds the small
source catalog used by both dropdowns; normal builds and static packaging
include it automatically. Dataset/grouping choices persist in the URL and
exports. Run `python scripts/check_flow_source_pages.py` after packaging.
See the [API and examples](../../experiments/docs/Revision%20Flow%20Builder.md)
and `src/revisionFlowExample.js` for inventory grouped by region or department.

## Reused and shared components

- `WorkbenchHeader.jsx`: six FMR navigation items supplied by the entry point.
- `SortableTable.jsx`: sorting over all filtered rows, with optional pagination.
- `ShareLink.jsx`, `modalLifecycle.js`: shared links, native dialogs, focus restoration.
- `PdfPreview.jsx`: lazy PDF.js viewer with page, fit, zoom, and original download.
- `FmrApp.jsx`: the same source tree/evidence component for both FMR documents.
- `fmrModel.js`: project filters, allocation statistics, comparison rows, and CSV exports.
- `Fmr.css`, `styles.css`: FMR presentation and the existing workbench styles.

## Validation

```sh
npm test --prefix analysis/web
node analysis/web/src/fmrSmoke.mjs
node analysis/web/src/geoSmoke.mjs
python -m unittest discover -s other-analysis/tests -v
python -m unittest discover -s analysis-nia/tests -v
python -m unittest discover -s gps-analysis/tests -v
python scripts/check_fmr_pages.py
python scripts/check_nia_pages.py
python scripts/check_hfep_pages.py
```

The browser checks run after build and packaging and require Python Playwright
and Chrome/Chromium. The FMR suite exercises all six tabs at mobile and desktop
sizes, tree expansion, deep links, global sorting, pagination, CSV downloads,
reviewed images, stacked dialogs, Highlight evidence, Analysis drill-downs,
mobile overflow, route-backed comparison sorting/paging, JSON exports, and all
four source/control PDFs with byte ranges. NIA checks cover the original
Analysis views, allocation shares, filtered funding reconciliation and pairing
coverage, concentration drilldowns/exports, AI monitoring filters/exports, and source PDF evidence. To test the development server
directly, set `FMR_WORKBENCH_URL=http://127.0.0.1:5173/` (or the NIA/HFEP
equivalents). Screenshots are saved under `/tmp/*-ui-verification/`. The render
smoke check exercises loaded data in all main views and common deep links,
rather than rendering only the loading shell.

See [FMR workbench guide](../../other-analysis/FMR_WORKBENCH.md) and
[NIA workbench guide](../../analysis-nia/NIA_WORKBENCH.md) for source and
matching limitations. The combined workbench deploys to GitHub Pages from `main`
after the workflow's data, unit and browser checks pass.
